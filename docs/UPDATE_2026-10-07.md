## 2. Founder metrics accuracy (`/admin/metrics`, `app/api/metrics/route.ts`)

- **#49, creator timing:** creators were bucketed by `auth.users.created_at`. A magic-link *request* creates that row, so someone who requested on Sep 17 and first signed in on Oct 6 was counted in the wrong week. Creators now use `email_confirmed_at` (falling back to `created_at`), which matches when the founder notify email fires.
- **#49, creator definition:** a creator is now an **accepted organization owner**. Invited co-admins and signed-in users with no org are shown separately under the hero (this week and all time) and are not counted as creators or in the activation funnel.
- **#51, events and signups:** weekly "new events" and "signups" now come from PostHog server-side events (`event_created`, `signup_batch_created`) via HogQL (`lib/posthog-query.ts`). The DB only holds rows that still exist, so deleted events and cancelled signups were dropping out of their week (e.g. week of Sep 14: 10 created vs 5 in DB). Falls back to DB counts if PostHog is unreachable, and the page labels which source it used. "Signups" now means form submissions, not slots.
- **Data fix (prod, one-off):** inserted the 14 missing `organizer_profiles` rows for users who had signed in but had no profile.
- **PostHog cross-check:** creator counts are reliable. PostHog has no first-sign-in or org-created event, so `user_signed_in` overcounts (it includes repeat sign-ins). `login_magic_link_sent` sends raw email addresses to PostHog (a PII concern; not yet addressed).

## 3. Bot protection

- **#50:** Vercel BotID (invisible challenge) on `POST /api/auth/send-magic-link`. Files: `next.config.js` (`withBotId`), `instrumentation-client.ts`, and a `checkBotId()` gate before the existing rate limits. Verified on prod: plain `curl` gets a 403, and the real browser login form works. Background: ~1,000+ never-confirmed magic-link accounts, about 32 per week.
- Optional: enable BotID Deep Analysis in Vercel → Firewall.

## 4. Event cover images (flag-gated)

- **Feature flag:** `NEXT_PUBLIC_FEATURE_COVER_IMAGE_ORG_IDS` (comma-separated org UUIDs, non-sensitive, read on both server and client; `lib/cover-image-feature.ts`). Currently it contains only **Smoke Test Eva** (`50acfa4e-d6c5-44e4-93e1-a77c7d2b60c7`). It gates the admin and edit upload UI, `/api/upload` cover uploads, and every place a cover is rendered (event page, flyer, OG image, invite email). The edit-page cover upload had previously been live for everyone; it is now gated too.
- **#16:** client-side resize, cover rendering, and storage cleanup of replaced or removed covers (only cover-shaped paths, LIKE-escaped, and skipped when a duplicated event still references the file). **Security fix:** the cover URL in invite emails is now query-stripped and HTML-escaped. Previously an admin-writable `?x=">` could inject HTML. Public pages fetch covers from `GET /api/events/[id]/cover`, because the public RPC omits `organization_id`.
- **#52, reposition:** new column `campaigns.cover_position` (CSS object-position, CHECK-validated; migration `20261007120000_campaign_cover_position.sql`, applied to prod manually). `PATCH /api/events/[id]/cover` saves it (event admins only, flag-gated). `components/CoverImageFrame.tsx` provides a fixed 2:1 frame with `object-fit: cover` (never stretched) and drag-to-reposition with Save and Cancel. The position applies on admin, edit, event page, flyer (now a fixed 2:1 frame) and the OG image (Satori support for `objectPosition` is unverified). It resets on replace or remove. Resize now scales to *cover* 1600×800.
- **#53, limits:** JPEG/PNG/WebP only; originals up to 20 MB (downscaled in the browser); clear errors for an unreadable image and for over 5 MB after resize (the server limit). Shared helper: `lib/cover-upload.ts`.
- **#55, controls:** "Add cover" sits in the admin action row next to Edit / Preview / Print flyer (and in the mobile More menu). When a cover exists, Change, Remove and Reposition are overlaid on it. The size hint sits under the cover: **1600 × 800 px (2:1), at least 1200 × 600, up to 20 MB.**
- **#54:** Supabase storage `cacheControl` now takes seconds (`"31536000"`); the old full-header string left uploads served as `no-cache`. URLs carry `?v=`, so long caching is safe. This applies to new uploads only.

Added `docs/GOOGLE_OAUTH_VERIFICATION.md` (scope justifications and a verification script that relies on automatic sync, not a "Sync now" button).
